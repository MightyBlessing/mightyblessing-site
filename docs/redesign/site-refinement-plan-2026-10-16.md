## 1. 작업 범위와 완료 원칙

사용자 최신 지시: **“수정요청 받은건 다해야지.”**

Slack QA 피드백 17개와 운영 검토 8개 주제를 합친 **R01~R20 모두를 수정·검수 대상**으로 둔다. 6개는 작업을 함께 처리하기 위한 묶음이다. 항목을 제외하거나 일부만 끝내는 기준이 아니다. 앞선 재검토에서 사진 크기·푸터 링크·같은 제품 사례 연결을 유지로 돌리고, 사진·제품 화면·레이아웃을 후속으로 분리했던 결정을 철회한다.

과잉 구현은 기존 코드·콘텐츠·컴포넌트 활용으로 줄인다. 요청된 결과를 생략하는 방식으로 줄이지 않는다. 원래 요청을 달성할 더 간단한 방법이 있으면 그 방법을 쓰고, 실제 결과를 요청별로 검수한다.

- 20개 항목 모두에 구체적인 수정과 완료 기준을 둔다. 최신 상태는 [적용 결과](site-refinement-results-2026-10-16.md)를 따른다.
- 자료가 부족한 항목도 범위 안에 둔다. 보유 자료와 확인 가능한 출처를 먼저 조사하고, 남은 자료가 필요하면 정확한 대상·종류를 명시한다.
- 자료 대기·일부 구현 상태를 전체 완료로 표시하지 않는다. 항목을 그대로 두는 변경안이 필요하면 근거를 제시하고 사용자가 받아들인 경우에만 대안으로 종결한다.
- 실제 행사·제품·수행 사실과 공개 권한을 지킨다. 사진이나 UI를 꾸며 만들거나 제외된 원본·보류 행사를 임의로 복원하지 않는다.
- 원본 서체·퍼플·실제 필름·타이포·기존 주소를 보존하면서 문구·배치·탐색을 개선한다.

### 확인 근거의 시점

- 앞선 10/16 운영 조사: 주요 6페이지·행사 30개·기존 종합 사례 3개·정책 2개 등 41페이지 본문. 주요 6페이지의 1440×900·390×844 화면 확인.
- Slack: 10/15 QA 댓글 19개 중 피드백 17개. 첨부 15개 중 14개 열람, 1개 조회 실패는 같은 의견의 보충 캡처로 대조. 원문별 대응은 6절에 보존.
- 당시 운영 검색: `welove` 15건 / `위러브` 3건 / `vj` 1건. 링크 목적지와 새 탭 속성도 확인.
- 계획 작성 이후 사용자 구현 요청에 따라 로컬 적용과 검수를 진행했다. 사진 4개 행사와 포도나무 관리 화면은 사용자가 후속 등록하기로 했다. 운영 재배포 상태는 아니다.

자료 확인은 작업 시작부터 진행하고, 독립적인 코드·문구 수정도 이어서 수행한다. 여섯 묶음의 완료는 아래 R01~R20의 완료 조건으로 판단한다.

### 구현은 필요한 만큼만

- [현재 검색 함수](../../lib/project-search.ts)의 `search_terms`와 [목록](../../app/portfolio/page.tsx)의 결과 수·초기화·URL 조건 저장을 활용한다. 별칭 보완으로 해결되는 문제에 새 검색 엔진을 도입하지 않는다.
- 두 제품의 사례는 [확인된 적용 관계](../../lib/product-projects.ts)에서 고른다. 포도나무는 CAMPUS, LIVE TEXT는 WELOVE 화해처럼 확인된 서로 다른 공개 사례를 우선 검토한다. 자료·설명이 해당 제품의 쓰임을 실제로 뒷받침해야 한다.
- 소개 링크는 중복을 제거하거나 문구와 목적지를 맞춘다. 차이를 만들기 위한 빈 섹션을 추가하지 않는다.
- [기존 상세 경로](../../app/portfolio/[slug]/page.tsx)의 표시와 기존 컴포넌트를 우선 활용한다. 화면 개선에 필요하지 않은 원고 스키마 이관·관리자 개편을 추가하지 않는다.
- 문구 중복을 먼저 줄인 뒤 해당 페이지의 여백·배치를 조정한다. 페이지별로 매번 새 디자인 체계나 모션 라이브러리를 만들지 않는다.
