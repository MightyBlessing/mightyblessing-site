## 동작 기준

- 저장 후 프로젝트 주소는 바꾸지 않는다. 기존 종합 사례의 상세 주소와 데이터 형식도 보존한다.
- ‘초안 저장’은 초안으로 전환한다. 공개를 유지하려면 ‘공개 상태로 저장’을 사용한다. 운영 노출 변경은 빌드·배포 뒤에 적용된다.
- 날짜는 정렬 기준이다. ‘표시 날짜’는 기간·월 단위 표기를 위한 항목이며 날짜를 바꾸면 초기화된다. 기존 표시 날짜를 그대로 유지하는 일반 편집은 보존한다.
- 홈 순서는 현재 지원하는 1~4번을 사용하며, 공개 상태이고 대표 사진 또는 영상 포스터가 있는 앞의 두 건이 현재 홈에 표시된다. 같은 번호는 새로 저장한 프로젝트가 가져간다. 전체 프로젝트 색인은 날짜순을 유지한다.
- 관련 사례는 직접 선택한 발행 문서만 표시한다. 보관 문서나 초안을 선택해도 공개 링크를 만들지 않는다.

## 검수 환경과 증거

- 원본 작업 폴더의 기존 `content/`와 `input/`은 수정하지 않았다. 브라우저 저장은 `/private/tmp/mb-admin-functional-l6gomqxb`에 복사한 앱·콘텐츠와 임시 관리자 계정으로 수행했다.
- GitHub·Supabase 운영 자격증명을 사용하지 않고 로컬 저장 어댑터로 실행했다. 파일 업로드의 multipart 전달·검증·실패 복구·충돌은 자동 검사에서 대체 저장 서비스를 사용했다. 실제 외부 업로드·GitHub 커밋·운영 재배포는 이번 검수 범위에 포함하지 않았다.
- 초기 임시 환경에서 `node_modules` 심볼릭 링크로 인해 요청 컨텍스트 오류가 발생했다. 의존성을 별도로 복사하고 임시 빌드 캐시를 새로 생성한 뒤 저장 요청이 정상 처리됨을 확인했다. 운영 코드로 우회하지 않았다.
- 실제 브라우저: 필수값 누락 400과 오류 표시, 신규 발행과 목록 노출, 날짜 초기화·기간 표시, 갤러리 파일 선택 후 삭제·저장, 저장된 주소 잠금, 홈 순서 변경, 추가 정보·관련 사례 표시, 영상 재생, 초안·발행·보관, 보관 후 상세 404, 로그아웃을 확인했다.
- 관리자 화면 1440×600과 390×844에서 가로 넘침이 없고 세 저장 버튼과 결과 안내가 표시된다. 모바일 상세 영상도 가로 넘침 없이 재생된다.
