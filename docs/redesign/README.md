**문구 수정:** [전체 사이트 문구 검수·수정](copy-review-2026-09-09.md). 홈·회사·제품·문의와 프로젝트 38개의 표현을 실제 수행 사실에 맞춰 정리했다. 사용자 요청에 따라 공개 화면의 제외 범위 나열을 제거하고 실제 맡은 일을 설명한다. 원본의 제외 정보와 상세의 필요한 크레딧은 보존한다. 날짜 정밀도·중복 연도도 보완했으며 테스트 102개·타입·Webpack 빌드를 통과했다. 글자 크기·자간 등 타이포 제안의 구현과는 별도다.

**Sites 검수:** [팀 검수 사이트와 갱신 방법](sites-review.md). 현재 화면을 별도의 Codex Sites 사본으로 준비했다. 프로젝트 35건·상세 38건·홈 필름을 포함하며 문의 입력은 발송되지 않는다. 기존 운영 사이트의 공개 상태·배포와 분리한다.

1. 사용자 최신 지시와 [작업 기준](../../AGENTS.md)에서 이번 범위와 보존 원칙을 확인한다.
2. [전체 색인·홈 하단 개선 결과](sidebar-home-improvement-results.md)에서 최신 적용과 검수 범위를 읽고, [실제 사이트 구현 기록](site-implementation.md)과 해당 코드를 대조한다. 이전 [UI/UX 업데이트 계획](uiux-update-plan.md)과 구현 기록의 폭·높이는 출발점이다. 새 계획과 이미 적용된 결과를 구별한다.
3. 작업 대상에 맞춰 [PRD](../prd.md), [설계](architecture.md), [디자인](design-tone.md), [콘텐츠](content-plan.md), [검수표](acceptance.md)를 참고한다. 과거 값과 미구현 요구가 남아 있으므로 문서의 모든 항목을 현재 구현이나 새 디자인의 고정 조건으로 취급하지 않는다.
4. 과거 시안은 아래 변경 이력에서 필요할 때만 읽는다. 파일 안의 ‘최신’이라는 표현보다 실제 날짜·사용자 결정·대체 관계를 우선한다.

**현재 구현:** 공통 `SiteFrame`으로 홈·목록·상세·문의·회사 페이지의 탐색을 통합했다. `/capabilities`·`/about`·`/products`는 구현되어 있고 `/services`는 `/products`로 308 이동한다. `/`와 `/design-system?view=home`은 같은 `ProductionHome`을 사용한다. 데스크톱 왼쪽 탐색·오른쪽 가변 콘텐츠, 모바일 상단 메뉴·프로젝트 대화상자가 현재 구조다. 실제 검토 주소는 [127.0.0.1:3017](http://127.0.0.1:3017/)이며 실행 전제와 명령은 [루트 README](../../README.md)에 있다.

**상태 구분:** 현재 로컬의 현장 필름과 검토 자료는 최종 공개 승인을 뜻하지 않는다. 개발 색인 35건과 운영 공개 3건을 구별하고, 필름의 운영 공개·배포는 별도로 다룬다. 이전 테스트 수·스크린샷은 당시 결과이며 다음 UI/UX 변경의 통과 근거로 재사용하지 않는다.

## 이번 프로젝트의 범위

| 영역 | 개선할 경험 |
|---|---|
| 공통 구조 | 정보 위계·메뉴·프로젝트 탐색·페이지 간 연결·푸터를 일관되게 구성 |
| 홈 | 회사의 분야와 감도, 실제 작업, 다음 행동을 여백·타이포·현장 미디어로 전달 |
| 프로젝트 목록·상세 | 원하는 사례를 찾고 실제 맡은 일·필요한 크레딧을 이해한 뒤 문의로 이동 |
| 하는 일·소개·제품 | 맡길 수 있는 범위, 일하는 방식, 제품의 쓰임과 독립 이용 경로를 명확히 설명 |
| 문의 | 입력·오류·진행·메일 작성·접수 상태를 구별하고 문의 흐름을 단순하게 구성 |
| 모바일·접근성 | 좁고 낮은 화면, 터치·키보드, 모션 감소와 실패 상황에서도 핵심 정보·탐색 유지 |

관리자 인증·콘텐츠 저장·메일 공급자·CI·운영 배포에서 발견한 문제는 별도 개선 과제로 관리한다. UI/UX 연결 부분은 확인하되 이번 프로젝트를 요청 없이 백엔드 전면 개편으로 확대하지 않는다. 운영 전 필요한 보완을 완료된 것으로 표시하지 않는다.

## 작업 흐름과 판단 기준

1. 실제 화면과 사용자 피드백을 확인하고 이번에 해결할 문제·대상 화면·기대 동작을 정한다.
2. 전체 정보 구조와 탐색을 기준으로 공통 레이아웃·여백·타이포·콘텐츠 위계를 검토한다. 기존 승인 방향과 원본 브랜드에서 이어서 설계한다.
3. 대표 화면을 로컬에 구현하고 관련 페이지와 모바일에 연결한다. 합리적인 세부 선택은 요청 범위에서 진행하고, 방향을 결정할 정보가 부족할 때만 질문한다.
4. 변경에 필요한 데이터·타입·lint·빌드 검사와 실제 브라우저 검수를 수행한다. 클릭·상세 이동·뒤로가기·메뉴 닫기·폼 오류 등 실제 흐름을 확인한다.
5. 새 적용값·검수 환경·결과·남은 사항을 해당 구현 문서에 기록한다. 제안, 구현, 검수, 사용자 시각 승인, 공개 승인, 운영 적용을 각각 구별한다.

과거 C안·30장 전환·색인 프리뷰 등은 현재 완료 조건이 아니다. 해당 화면을 변경할 때 [검수표](acceptance.md)의 관련 항목도 새 방향과 함께 갱신한다. 기존 검수표의 링크·요구사항 ID가 유효하다는 사실은 새 UX가 적합하거나 구현 완료되었다는 의미가 아니다.

**직전 작업:** [홈 프로젝트 색인 구현·검수](sidebar-direction.md). 사진과 이름을 한 행으로 연결하고 홈 모바일 목록에도 적용했다. 기존 여섯 작업·히어로·상세/아카이브 35개 목록은 유지한다. 상세 규격, 캡처, 자동 검증과 미검수 환경을 해당 문서에 구분했다. 평가 후 썸네일별 구도, 호버 면 좌우 4px 여백, 세로로 긴 데스크톱의 공통 높이 상한을 [9절](sidebar-direction.md#9-평가-후-구도와-여백-보정)에 추가했다. 일반 화면의 히어로 비율과 사진·타이포 재생은 유지한다.

1. **[이전 30장 히어로](hero-editorial-sequence.md)** — 당시 승인 방향과 검수. 실제 사진 30장, 첫 세 장의 12초 편집, 두 줄 중앙 조판, 글자 착지와 사진 컷 연결, 색인 정리. [직전 30장 시안](playful-photo-hero.md)은 당시 기록으로 보존한다. [이전 중앙 필름](center-type-film.md)과 [이전 단일 사진](photo-type-hero.md)은 당시 근거와 검수로 보존한다.
2. [레퍼런스 심층 분석](reference-deep-analysis.md) — 탐색 구조·편집·비율 해석. 원본 로고·서체·색을 유지하며 회사소개서는 사실과 역할의 근거로 사용한다.
3. [전체 디자인 가이드](design-tone.md) · [디자인 시스템](design-system.md) · [설계서](architecture.md) · [PRD](../prd.md) — 공통 기준. 최신 히어로와 충돌하는 과거 지침은 적용하지 않는다.
4. [이전 타이포 전용 계획](typography-hero-plan.md) · [이전 구현](typography-hero-implementation.md) · [회사 설명+사진 홈](home-rebuild.md) — 과거 구현·검수 기록. 현재 시안의 기준이 아니다.

사진은 공개 승인 대기의 개발용 파생본이며 `draft`를 유지한다. 실제 운영 공개·배포는 수행하지 않았다. 기존 전체 프로젝트와 상세·문의·제품 연결·분석 코드를 유지했다.

## 현재 자료에서 확인한 사항

다음 수치와 자료 대조는 이전 자료 조사 시점의 기록이다. 이번 지침 정리에서 원본 전체를 재집계하거나 외부 레퍼런스를 다시 검증한 결과가 아니다.

- input 일반 파일 3,855개, 34,790,685,069바이트(약 34.79GB). 바로가기 25개 중 2개는 깨져 있다. 파생본·보고서도 포함하며 고유 사진 수가 아니다.
- 원본 분류 CSV 1차 189행+2차 3,275행 = 3,464행 모두 현재 workspace에서 파일 경로 존재를 확인했다. 원본 해시를 새로 전수 계산하지 않았다.
- v10 이력 37행을 CSV로 정리하고 26개 우선 미디어 후보를 연결했다. ‘37건 전체 제작’으로 해석하지 않는다.
- 최신 v10에서 제품 공개 UI·데모와 REG_WIDE 등록 사진을 확인했다. 기존 부족 목록을 그대로 반복하지 않는다.
- v06 CUE_EXCERPT 바로가기는 전체 원본 큐시트를 가리킨다. 공개 발췌본으로 사용하지 않는다.
- CAMPUS 일자는 v10 정정값 2026.07.25, MultiTracks 키비주얼은 본사, 음향 제외 및 F.I.A 부분 운영 범위를 반영했다.
- 두 레퍼런스 홈은 웹 문서와 실제 데스크톱 화면을, Chris & Partners 상세는 실제 브라우저에서 확인했다. 모바일 레퍼런스의 실기기는 검증하지 않았다. 우리 사이트의 별도 로컬 검증 범위는 첫 구현 검토 안내에 기록했다.

## 이전 단계의 작업 묶음

디자인은 전체 가이드→스타일 보드→대표 정지 화면→반응·모션→앱 적용 순으로 진행한다. 아래 기능 제작 순서는 이 디자인 검토를 건너뛰는 지시가 아니다.

1. **콘텐츠 결정:** 홈 선별 2·전체 색인 35건의 역할/사진과 히어로 편집안을 함께 검토. THE SENT 26 등 미확인 후보는 별도 보류.
2. **핵심 디자인:** 홈 데스크톱·홈 모바일·프로젝트 상세를 실제 콘텐츠로 함께 설계. 긴 이름·적은 사진·오류 상태 포함.
3. **구현:** 스키마와 기존 콘텐츠 이관→공통 셸→목록·상세→나머지 페이지→문의·관리자→운영 검증.

기존 PRD는 [archive](../archive/prd-v1.md)에 보존했다. 앱은 첫 구현을 반영했으며 원본 input은 변경하지 않았다. 위 작업 묶음의 전체 완료를 의미하지 않는다.
